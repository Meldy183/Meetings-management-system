# Выгрузка реестра участников в XLSX

Утилита `export-participants` читает **всю** таблицу `public.participants`: в том числе людей, не привязанных к встречам, и записи с одинаковыми ФИО. Сортировка соответствует алфавитному виду вкладки «Реестр»; при одинаковых ФИО порядок определяется ID.

Один лист «Реестр», колонки: **Фамилия, Имя, Отчество, Информация, ID**. Первые четыре колонки совместимы с текущим Excel-импортом приложения; пятая сохраняет идентификатор записи. Значения выгружаются как текст, без обрезания пробелов или интерпретации формул. Пустой реестр даёт файл с заголовками.

## На сервере с уже работающим Docker Compose

Запускать из каталога проекта и с тем же Compose project name, которым запущено приложение. Если запускали приложение с `-p NAME`, добавьте тот же `-p NAME` в обе команды ниже.

```bash
mkdir -p outputs
docker compose --profile export build export-participants
EXPORT_UID=$(id -u) EXPORT_GID=$(id -g) docker compose --profile export run --rm --no-deps export-participants
```

Результат: `outputs/participants-YYYYMMDD-HHMMSS.xlsx`. Команда печатает число выгруженных записей и имя файла. Чтобы задать имя явно, добавьте `-out /exports/registry.xlsx` в конец последней команды.

Сервис экспорта не имеет `depends_on`; команда с `--no-deps` запускает только утилиту. Она не запускает/останавливает PostgreSQL, приложение, миграции или тесты, не удаляет volume и не меняет записи или схему. Пересоздавать приложение для выгрузки не требуется.

По умолчанию подключение соответствует БД из этого `docker-compose.yml`. Если у работающей БД другие реквизиты, задайте `EXPORT_DATABASE_URL` через окружение или `.env`; не передавайте пароль аргументом командной строки. Утилита совместима с отдельным пользователем БД с правами только на чтение.

Чтобы скачать файл на свой компьютер:

```bash
scp -i /путь/к/ключу.pem ubuntu@IP_СЕРВЕРА:/путь/к/проекту/outputs/participants-YYYYMMDD-HHMMSS.xlsx .
```

## Без Docker

Нужен Go 1.24 или новее и сетевой доступ к уже запущенному PostgreSQL.

```bash
cd backend
go build -o /tmp/export-participants ./cmd/export-participants
export DATABASE_URL='postgres://USER:PASSWORD@HOST:5432/meetings_editor?sslmode=disable'
/tmp/export-participants -out /путь/к/registry.xlsx
```

`DATABASE_URL` обязателен: автоматического выбора БД нет. Для удалённого соединения используйте режим TLS и реквизиты вашей БД.

## Ограничения и проверки

Соединение устанавливает `default_transaction_read_only=on`; SELECT выполняется в транзакции `READ ONLY`, которая заканчивается rollback до создания XLSX. Используется одно соединение, запрос имеет лимит 30 секунд и ожидание блокировок не более 2 секунд. Чтение не блокирует обычные INSERT/UPDATE/DELETE. После чтения соединение закрывается; файл создаётся локально.

Существующий файл никогда не перезаписывается. При превышении лимитов XLSX (1 048 575 записей плюс заголовок, 32 767 символов в ячейке) утилита завершится с ошибкой вместо незаметного обрезания данных. Частично записанный файл удаляется при ошибке записи.

Тесты утилиты работают без подключения к БД:

```bash
cd backend
go test ./internal/registryexport ./cmd/export-participants
```

Не запускайте `tests.sh` или существующие repository-тесты для проверки выгрузки на рабочей БД: они предназначены для отдельной тестовой БД и могут очищать данные.
